# 智能文档清理器 - 技术文档

## 1. 项目概述

基于 [yangbin09/smart-file-cleaner](https://github.com/yangbin09/smart-file-cleaner)（Python 3.13 + tkinter）改造。
上游是一个交互式命令行清理工具，本次改造补齐了：真实删除能力、文件名日期判定、
回收站/备份双保险、桌面 GUI、内置定时调度、托盘后台运行、报告留存，并完成打包交付。

## 3. 核心设计

### 3.1 动态加载架构（上游遗留，改造需迁就）

上游所有模块经 `utils/import_helper.py` 的 `import_module_from_path()` 按**文件路径**
用 importlib 动态加载（模块名含连字符，无法常规 import）。带来的影响：

- 删除保护：清理逻辑按扩展名白名单放行，代码/配置/程序扩展名永不删除
- **打包影响**：PyInstaller 静态分析看不到这些模块 → 必须把整个 `src/` 作为
  `datas` 原样打进包，运行时从磁盘 `_internal/src/` 动态加载（见 §5）

### 3.2 删除流程（`BaseProcessor._delete_file`，processor-factory.py）

```
过期判定 → 按 create_backup 复制到 backups/ → 
按 use_recycle_bin 走 PowerShell Shell API（Microsoft.VisualBasic.FileSystem.DeleteFile
  + SendToRecycleBin）→ 失败回退 os.remove → 记录 deleted_files
```

回收站实现：`powershell -Command` 调 VB 互操作 COM，无需额外依赖；失败自动回退硬删。

### 3.3 过期判定（cleaning-strategies.py）

`AgeBasedCleaningStrategy` 支持文件名日期解析（`2024-01-15` / `20240115` / `2024年1月15日` /
`2024_1_15` 等），无日期或解析失败退回最后修改时间；`create_age_cleaning_context()` 生成
`{max_age_days, use_filename_date}` 上下文。判定顺序：扩展名白名单 → 文件名日期 → mtime → 阈值。

### 3.4 控制器模式（file-processor-controller.py）

| 模式 | 入口 | 行为 |
|------|------|------|
| 无人值守 | `run_auto_mode()` | 读配置 → 预览 → 直接执行（不询问）→ 存报告 |
| 预览 | `run_preview_mode()` | 只扫描标记，不删除 |
| 交互（上游） | `run_interactive_mode()` | 保留上游菜单，需确认 |

`_process_directory(target, dry_run)` 统一执行：dry_run=True 仅标记，False 走删除。
`processing_results` 记录每目录结果，`_save_auto_report()` 只取 `dry_run=False` 的成功项
写 `reports/cleaning_report_时间戳.json`。

### 3.5 GUI（src/gui/app.py）

- 单窗口 tkinter，分 6 区：目录 / 规则 / 格式 / 安全 / 定时自启 / 报告日志
- 文件格式：内置三类扩展名（文档/图片/临时，与 `file_types_config` 一致）+ 自定义输入
- 执行链路：`subprocess` 起 `main.py --auto/--preview` 子进程（`CREATE_NO_WINDOW`），
  逐行读 stdout 实时显示到日志区——避免 GUI 线程里跑清理阻塞界面
- 配置读写：`_load_config()` 深合并默认值，`_save_from_ui()` 界面→JSON
- 报告查看：`_refresh_reports()` 扫 `reports/`，点选后读 JSON 提取摘要打印到日志区

### 3.6 定时调度（src/gui/scheduler.py）

`AutoCleanScheduler`：守护线程循环，算到下一个 HH:MM 目标点 `Event.wait(timeout)`
睡到点，触发回调；`last_run_date` 防同一天重复补跑；`update_time()` 运行时改时间，
无需重启。托盘模式（--tray）下同样运行，实现"开机自启 + 无窗口 + 定时清理"。

### 3.7 托盘（src/gui/tray.py）

pystray 动态导入（缺失降级为纯窗口模式），运行时生成 64x64 图标，
菜单：打开主界面（默认项）/ 立即清理 / 退出。图标绘制用 Pillow `ImageDraw`。

### 3.8 开机自启

写注册表 `HKCU\Software\Microsoft\Windows\CurrentVersion\Run` 的 `SmartFileCleaner` 项：
源码版 = `pythonw main.py --tray`，打包版 = `"<exe路径>" --tray`（GUI 勾选即写/删）。

## 5. 打包交付（实测验证）

### 5.1 PyInstaller（SmartFileCleaner.spec）

```
python -m PyInstaller --noconfirm --clean SmartFileCleaner.spec
```

关键配置：

| 项 | 值 | 原因 |
|----|----|------|
| `console=False` | 无控制台窗口（GUI 程序） | 子进程输出靠管道捕获 |
| `datas: src → src` | 整目录收集 | 动态加载模块从磁盘读源文件 |
| `datas: config.yaml → .` | 兜底 YAML | yaml_config_loader 默认路径 |
| `hiddenimports: yaml` | 强制收集 | 上游 try/except 导入易漏 |
| `excludes: numpy 等` | 减体积 | 无关依赖 |

### 5.2 frozen 路径适配（重要）

打包后与源码路径语义不同，三处代码做 `sys.frozen` 分支：

| 位置 | 源码 | 打包 |
|------|------|------|
| main.py `src_dir` | `__file__/src` | `sys._MEIPASS/src`（只读源码） |
| main.py `APP_DIR` | 项目根 | `exe 所在目录`（配置/报告/备份落这里） |
| controller `_load_operation_config` | `__file__` 上溯 | `exe 旁 config/` |
| GUI `CONFIG_PATH` | `src/config/` | `exe 旁 config/` |
| 子进程调用 | `python main.py --auto` | `exe --auto`（自身） |
| 开机自启 | `pythonw main.py --tray` | `exe --tray` |

> 用户数据（config/reports/backups）永远在 **exe 旁边**，升级安装不丢；
> `_internal/` 只读源码与依赖。

### 5.3 实测验证清单（全部通过）

1. `--preview`：打包版输出正确（PyYAML 正常加载，不再报"未安装"）
2. `--auto`：读 exe 旁配置 → 目标目录正确 → 旧文件按文件名日期识别
   （596 天前）→ 已移入回收站 → 报告生成
3. GUI 无参数启动、`--tray` 托盘模式：进程驻留正常
4. 源码版全链路回归：预览/清理/报告/回收站恢复均正常

### 5.4 Inno Setup（setup/SmartFileCleaner.iss）

```
ISCC setup\SmartFileCleaner.iss   # 脚本含中文必须 UTF-8 BOM
```

- 安装到 `{autopf}\SmartFileCleaner`，可选开机自启（注册表 Run，卸载自动清理）

## 6. 已知限制

- **坑：Inno 6 官方安装包不带中文语言文件**（Languages 目录无 ChineseSimplified.isl），
  安装向导为英文界面，应用内全中文
- GUI 子进程清理与内置调度并发执行时各自独立（调度到点 + 用户点清理会跑两次），
  无互斥锁——正常使用不会同时发生，属可接受
- 上游遗留警告（无害，勿修）：`No module named 'src.config.app_config'`、
  `name '_import_module_from_path' is not defined`，均自动回退可用路径
